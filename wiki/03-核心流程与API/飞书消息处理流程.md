# 飞书消息处理流程

## 流程概述

飞书用户发送私聊或群聊 @ 消息后，飞书平台回调 CodexClaw 的 `/webhook/feishu` 端点。服务在 3 秒内返回 `{"code": 0}`，实际消息处理在后台 asyncio task 中异步完成：去重 → 命令分发 → 会话拼接 → CLI 调用 → 流式回复 → 图片管线 → 会话写回。

## 流程图

```mermaid
graph TB
    A[飞书 Webhook] --> B[签名校验]
    B --> C{URL verification?}
    C -->|是| D[返回 challenge]
    C -->|否| E[事件解析]
    E --> F[Token 校验]
    F --> G[异步 task 启动]
    G --> H[去重检查]
    H --> I{/stop?}
    I -->|是| J[取消任务]
    I -->|否| K[Quick Ack reaction]
    K --> L{已有运行任务?}
    L -->|是| M[回复忙]
    L -->|否| N[命令分发]
    N --> O{是命令?}
    O -->|是| P[执行命令]
    O -->|否| Q[/remind?]
    Q -->|是| R[登记提醒]
    Q -->|否| S[会话+CLI调用]
    S --> T[流式回复]
    T --> U[图片管线]
    U --> V[会话写回]
```

## 关键步骤

### 步骤 1：Webhook 接收与安全校验

- **触发条件**：飞书平台 POST `/webhook/feishu`
- **执行位置**：`lib/python/channel/feishu/handler.py:63`
- **操作内容**：解析 JSON → 校验签名（SHA256）→ 处理 challenge → 解析事件 → Token 校验
- **安全**：无签名且未加密且未配置 verification_token 时返回 401

### 步骤 2：去重与 Quick Ack

- **执行位置**：`handler.py:88-105`
- **操作内容**：`message_id` TTL 去重（1 小时）→ 发送 `Typing` reaction 快速回执

### 步骤 3：命令分发

- **执行位置**：`handler.py:134-159`
- **操作内容**：
  - `/remind` → 登记到 ReminderScheduler
  - `/skills` → `asyncio.to_thread(ClaudeCliClient._build_skill_summary)`
  - `/help /new /reset /compact /backend /codex /claude /qodercli` → `process_command`

### 步骤 4：会话拼接与 CLI 调用

- **执行位置**：`handler.py:161-232`
- **操作内容**：读取历史 → 拼接当前消息 → TaskRegistry 注册 → 启动长任务通知定时器 → 启动图片监控（如检测到画图意图）→ 流式/非流式调用 CLI

### 步骤 5：回复回传

- **执行位置**：`handler.py:266-316`
- **操作内容**：汇总流式片段 → 智能分段 → 三级回退回复（markdown → text → chat send）→ 图片上传与发送

## API 端点

### POST `/webhook/feishu`

**响应**：

| 状态码 | 说明 | 响应体 |
|--------|------|--------|
| 200 | 接受 | `{"code": 0}` |
| 401 | 签名/Token 校验失败 | `{"code": 401, "msg": "..."}` |
| 400 | 请求体格式错误 | `{"code": 400, "msg": "..."}` |

## 异常处理

| 异常场景 | 处理方式 | 相关代码 |
|----------|----------|----------|
| CLI 超时 | 终止子进程，回复"服务繁忙" | `handler.py:251-258` |
| 用户 /stop | kill 子进程，回复"当前任务已终止" | `handler.py:235-250` |
| 飞书 API 不可用 | 三级回退，最终降级到 chat send | `handler.py:642-690` |
| 图片上传失败 | 回复"图片已生成，但上传到飞书失败" | `handler.py:495-508` |

## 性能考量

- webhook 立即返回 `{"code": 0}`，处理在后台 task 中异步完成
- 图片扫描使用 `asyncio.to_thread` 避免阻塞事件循环
- 接收的临时图片在任务完成后自动清理
