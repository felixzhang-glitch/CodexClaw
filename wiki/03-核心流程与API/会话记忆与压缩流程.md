# 会话记忆与压缩流程

## 流程概述

CodexClaw 按 `user_id + chat_id` 维度维护多轮对话历史，默认保留 10 轮（FIFO 裁剪）。用户可通过 `/new` 新建会话、`/reset` 清空、`/compact` 压缩（将较早轮次合并为摘要，保留最近 2 轮原文），降低后续 prompt 体积。

## 流程图

```mermaid
graph TB
    A[用户消息] --> B[build_messages 拼接历史]
    B --> C[追加当前消息]
    C --> D[调用 CLI]
    D --> E[append_round 写回]
    E --> F{轮次超限?}
    F -->|是| G[FIFO 删除最早]
    F -->|否| H[完成]
    G --> H
    I[/compact 命令] --> J[读取全部轮次]
    J --> K[保留最近2轮]
    K --> L[较早轮次合并为摘要]
    L --> M[写回压缩后会话]
```

## 关键步骤

### 步骤 1：会话拼接

- **触发条件**：每次非命令消息处理时
- **执行位置**：`lib/python/channel/feishu/handler.py:161-162`
- **操作内容**：`session_manager.build_messages(key)` 读取历史 → 拼接 `[{"role": "user", "content": text}]`

### 步骤 2：写回与 FIFO 裁剪

- **触发条件**：CLI 返回答案后
- **执行位置**：`lib/python/core/session/manager.py` `append_round`
- **操作内容**：追加 user + assistant 轮次 → 超过 `MAX_HISTORY_ROUNDS` 时删除最早轮次

### 步骤 3：新建会话

- **触发条件**：用户发送 `/new`
- **执行位置**：`lib/python/app/commands.py:82-83`
- **操作内容**：`session_manager.new_session(key)` 生成新 session_id，不继承旧上下文

### 步骤 4：清空会话

- **触发条件**：用户发送 `/reset` 或后端切换时
- **执行位置**：`lib/python/app/commands.py:86-87`
- **操作内容**：`session_manager.reset_session(key)` 清空所有轮次

### 步骤 5：压缩会话

- **触发条件**：用户发送 `/compact` 或 `/compress`
- **执行位置**：`lib/python/app/commands.py:69-73`
- **操作内容**：`session_manager.compact_session(key)` 将较早轮次合并为一条摘要轮次，保留最近 2 轮原文

## 涉及模块

| 模块 | 角色 | 关键文件 |
|------|------|----------|
| 会话与任务管理 | 会话存储与裁剪 | `core/session/manager.py` |
| 应用入口与配置 | 命令解析 | `app/commands.py` |
| 飞书渠道 | 调用方 | `channel/feishu/handler.py` |
| 微信渠道 | 调用方 | `channel/wechat/handler.py` |

## 异常处理

| 异常场景 | 处理方式 | 相关代码 |
|----------|----------|----------|
| 会话不存在 | `build_messages` 返回空列表，仅使用当前消息 | `manager.py` |
| 压缩时轮次不足 | `compact_session` 返回 `(before, after)` 相等，回复"无需压缩" | `commands.py:71-72` |

## 性能考量

- 会话存储在内存 dict 中，读写 O(1)
- FIFO 裁剪在 `append_round` 中同步执行，轮次少时开销可忽略
- `/compact` 适合长会话降低后续 prompt 体积，减少 CLI token 消耗
- 会话历史和运行态控制解耦，便于后续替换成 Redis/DB
