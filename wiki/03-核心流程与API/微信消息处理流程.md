# 微信消息处理流程

## 流程概述

微信用户发送私聊消息后，iLink Bot API 推送给 sidecar，sidecar 长轮询获取后 POST 到 CodexClaw 的 `/webhook/wechat`。CodexClaw 同步处理（去重 → 命令分发 → CLI 调用 → 回复分段）并返回 `{"code": 0, "replies": [...]}`，sidecar 逐条发送回复。

## 流程图

```mermaid
graph TB
    A[微信用户消息] --> B[iLink Bot API]
    B --> C[Sidecar 长轮询]
    C --> D[handleInbound 去重]
    D --> E[POST CodexClaw Webhook]
    E --> F[Token 验证]
    F --> G[事件解析]
    G --> H[去重检查]
    H --> I{/stop?}
    I -->|是| J[取消任务]
    I -->|否| K{已有运行任务?}
    K -->|是| L[回复忙]
    K -->|否| M[/remind?]
    M -->|是| N[回复不支持]
    M -->|否| O[命令分发]
    O --> P{是命令?}
    P -->|是| Q[执行命令]
    P -->|否| R[会话+CLI调用]
    R --> S[回复分段]
    S --> T[HTTP 返回 replies]
    T --> U[Sidecar 逐条发送]
```

## 关键步骤

### 步骤 1：Sidecar 长轮询与消息接收

- **触发条件**：iLink Bot API 有新消息
- **执行位置**：`lib/js/wechat-sidecar.mjs:351-378`
- **操作内容**：`getUpdates` 长轮询 → 提取文本（含语音转文字）→ `handleInbound` 去重 → `postToCodexClaw`

### 步骤 2：CodexClaw Webhook 处理

- **执行位置**：`lib/python/channel/wechat/handler.py:61-72`
- **操作内容**：Token 验证（Bearer）→ 解析 payload → 构建 `WeChatTextMessageEvent` → 同步调用 `_handle_text_event`

### 步骤 3：命令分发与 CLI 调用

- **执行位置**：`handler.py:74-136`
- **操作内容**：
  - `/remind` → 拦截并返回"微信暂不支持"
  - `/skills` → `asyncio.to_thread(ClaudeCliClient._build_skill_summary)`
  - 其他命令 → `process_command`
  - 非命令 → 会话拼接 → CLI 调用（流式或非流式）

### 步骤 4：回复返回与发送

- **执行位置**：`wechat-sidecar.mjs:318-324`
- **操作内容**：解析 CodexClaw HTTP 返回的 `replies` 数组 → 逐条调用 `sendText` 发送到微信

## API 端点

### POST `/webhook/wechat`

**请求参数**：

| 参数 | 位置 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| message_id | body | string | 是 | 消息 ID |
| account_id | body | string | 是 | 账号 ID |
| user_id | body | string | 是 | 发送者 ID |
| text | body | string | 是 | 消息文本 |
| context_token | body | string | 否 | 上下文 token |
| Authorization | header | string | 是 | `Bearer <token>` |

**响应**：

| 状态码 | 说明 | 响应体 |
|--------|------|--------|
| 200 | 成功 | `{"code": 0, "replies": [...], "context_token": "..."}` |
| 401 | Token 校验失败 | `{"code": 401, "msg": "..."}` |
| 400 | 参数缺失 | `{"code": 400, "msg": "..."}` |

## 异常处理

| 异常场景 | 处理方式 | 相关代码 |
|----------|----------|----------|
| CodexClaw 超时 | sidecar 发送"服务繁忙"兜底 | `sidecar.mjs:340-344` |
| CLI 取消 | 回复"当前任务已终止" | `handler.py:130-131` |
| CLI 异常 | 回复"服务繁忙，请稍后重试" | `handler.py:133-134` |

## 性能考量

- 同步请求-响应模式：sidecar 等待 CodexClaw HTTP 返回后才发送回复
- sidecar 默认超时 300000ms（5 分钟），防止 CodexClaw 挂起时永久阻塞
- `activeInbound` Set 防止同一消息重复处理
