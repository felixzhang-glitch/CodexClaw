# 会话与任务管理

## 模块职责

管理用户会话历史（FIFO 裁剪、压缩）、消息去重（message_id TTL）、运行中任务注册与取消（kill 子进程）、单实例定时提醒调度与持久化。

## 关键文件

| 文件 | 职责 | 行数 |
|------|------|------|
| `lib/python/core/session/manager.py` | 会话存储与 FIFO 裁剪、压缩 | 95 |
| `lib/python/core/session/deduplicator.py` | message_id 去重 | 30 |
| `lib/python/core/session/task_registry.py` | 运行中任务注册与取消 | 63 |
| `lib/python/core/session/reminder_scheduler.py` | 单实例定时提醒与持久化 | 175 |

## 核心接口/类

### `SessionManager`

- **用途**：内存会话存储，按 `user_id:chat_id` 维度管理多轮对话
- **关键方法**：
  - `build_key(user_id, chat_id)` → 会话 key
  - `build_messages(session_key)` → 拼接历史消息列表
  - `append_round(key, user, assistant)` → 追加一轮对话，超限 FIFO 删除最早
  - `new_session(key)` → 生成新 session_id
  - `reset_session(key)` → 清空会话
  - `compact_session(key)` → 压缩较早轮次为摘要，保留最近 2 轮

### `MessageDeduplicator`

- **用途**：基于 message_id 的 TTL 去重
- **方法**：`seen(message_id)` → 返回 True 表示重复

### `ActiveTaskRegistry`

- **用途**：按会话维度管理运行中任务
- **关键方法**：
  - `start(key, trace_id, message_id, cancel_callback)` → 注册任务（同会话同时只能有一个）
  - `cancel(key)` → 触发 cancel_callback 终止任务
  - `finish(key, trace_id)` → 标记任务完成
  - `mark_notice_sent(key, trace_id)` → 标记长任务通知已发送

### `ReminderScheduler`

- **用途**：单实例 asyncio 定时提醒调度
- **关键方法**：
  - `schedule(chat_id, text, delay_seconds)` → 登记提醒并启动 asyncio task
  - `cancel(reminder_id)` → 取消提醒
  - `start()` → 启动时从 JSON 加载未到期提醒
  - `close()` → 关闭所有提醒 task
- **持久化**：`runtime/server/reminders.json`，原子写（`asyncio.to_thread` + `os.replace`）
- **失败处理**：回调失败时不删除提醒，保留以供下次启动重试

## 设计模式

| 模式 | 应用位置 | 意图 |
|------|----------|------|
| 注册表 | `ActiveTaskRegistry` | 会话维度任务注册，支持 cancel |
| 调度器 | `ReminderScheduler` | asyncio task 定时触发 |
| FIFO 队列 | `SessionManager` | 超限自动裁剪最早轮次 |

## 依赖关系

### 上游依赖

- **app.config**：`Settings` 读取 `max_history_rounds`、`deduplicate_ttl_seconds`、`reminder_store_path`

### 下游被依赖

- **channel.feishu.handler**：会话、去重、任务、提醒
- **channel.wechat.handler**：会话、去重、任务
- **app.main**：创建实例并注入 handler

## 注意事项

- 会话历史和运行态控制解耦：`SessionManager` 管历史，`TaskRegistry` 管运行态，便于后续替换成 Redis/DB
- 提醒持久化使用 `asyncio.to_thread` 执行文件 I/O，避免阻塞事件循环
- 提醒回调失败时不删除提醒，保留在内存和持久化文件中，下次启动时重新调度
- 同一会话同一时刻只允许一个运行中任务，重复请求返回"已有任务在运行中"
